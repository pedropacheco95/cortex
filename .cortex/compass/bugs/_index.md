**Read this when:** triaging a reported problem, or checking whether a failure mode was seen before.

**What's here:** one file per bug (B-NNN), seven-type classified. B-001 (wrong-rule), B-002 (missing-criterion), B-003 (incomplete-rule) — all **resolved**, each caught by the system's own mechanisms and kept as design-refinement history. B-004 (incomplete-rule, open — onboard scratch homes) and B-005 (missing-criterion, open — --force clobbers localised indexes) were found by the reconciliation pass. B-006 (missing-criterion, **resolved** — check.atlas wrongly required "id" on raw atlas/sources/ material; now sidecar-validated). B-007 (incomplete-rule, open — L1's NUL heuristic misclassifies NUL-containing .ts sources as binary) and B-008 (incomplete-rule, **resolved** — check.index-present flagged the extraction skill's transient pulse working dir; fixed in the pulse reports/state/extraction reorg by exempting the whole `pulse/` subtree below its root `_index.md`, schema §7.1 amended) were found dogfooding v3 insight extraction. B-009 (wrong-rule, **resolved**, high — Desktop scheduled tasks never registered; fixed via `cortex tasks register`/`verify`). B-010 (missing-criterion, **resolved**, high — session-observe's `rule-candidate` proposals could never be `pulse-accept`-ed; fixed by `ruleFilePayload()`, mirroring `decisionFilePayload()`). B-011 (test-defect, **resolved**, high — a `cortex sync` CLI-dispatch test with no injectable `home` leaked 45 real scheduled-task directories into the actual `~/.claude/scheduled-tasks/`; fixed by a `withHomeEnv()` test helper redirecting `process.env.HOME`). B-012 (missing-criterion, **resolved**, high — per-question `readline.Interface` create/close cycles could drop a buffered y/N answer across rapid sequential prompts, desyncing a scheduled-task payload's marker from its content; fixed by one shared interface per command invocation plus a defensive marker-hash invariant). B-014 (incomplete-rule, **resolved**, medium — the schema document advanced through 3.1/3.2/3.3 while `src/schema/version.ts` and `src/cli/templates.ts` both still declared 3.0, so `cortex validate` announced a contract three MINORs older than the one it enforced and `cortex init` scaffolded new projects against it; no check misbehaved — §10.2 backward-tolerance meant a 3.0 project always validated clean — so the damage was to the number's trustworthiness. Root cause: `schema.version-2` pinned one bump's literals and had no rule that the three declarations must track the contract. Fixed by the bump plus `schema.version-2` Rule 8 and a literal-free regression test that derives the version from the document). B-013 (incomplete-rule, **resolved**, high — `cortex init` had no guard against a target inside an existing Cortex layer, silently scaffolding a nested second Cortex inside `.cortex/`; fixed by a preflight check for an enclosing `.cortex`+`cortex.config.json` layer, refused even under `--force`).

**How to navigate:** `affects:` names the spec IDs / files involved; `type:` routes the fix (types 1–6 → spec change, type 7 → test/skill fix); resolved entries carry a Resolution section. The daily bug-triage loop fills absent classifications and reports divergences.
