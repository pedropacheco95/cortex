# A diagnosis names the cause, and a test proves the behaviour

## Outcome

When this works, the two signals a spec-first project relies on stop lying.

A filed bug names the cause someone actually found, not the layer that looked most likely from
the symptom. The developer reading the ledger a month later sees the evidence that produced the
classification, so they can tell a diagnosis from a guess.

A generated test is one the project has watched fail for the reason it claims to check. A test
that has only ever been seen passing is an unverified assertion wearing a test's clothing — it
may be passing because the behaviour is right, or because it asserts nothing, or because it
tests the wrong thing entirely. Nobody can tell which, and that is the failure.

## Who this is for

Developers on spec-managed projects where bugs are triaged and tests are generated by an
agent, and where nobody re-derives every diagnosis or re-checks every green test by hand.

## User Journey

1. Something breaks. Before anything is named or filed, the failure is reproduced and the
   boundaries around it are instrumented, so the report rests on observation.
2. Only then is the bug classified, and the evidence travels with the classification into the
   ledger.
3. When new behaviour is specified, its test is written first and watched failing — and the
   failure message is read, not just its presence noted, because a test can fail for a reason
   that has nothing to do with what it claims.
4. Code is written only after that observation. Code written before its test is deleted rather
   than adapted, because code that already exists shapes the test into agreeing with it.

## Business Rules

1. No classification is recorded before the cause has been investigated and evidenced.
2. A test counts as red only when it has been observed failing for the reason it exists to
   check — not merely failing.
3. Both disciplines state their excuses and their answers in writing, because the pressure to
   skip them is predictable.
4. Neither discipline mutates anything: diagnosis writes a bug file, test generation writes
   tests. Fixing remains a separate, later act.

## Success Metrics

- Every ledger entry can point at the observation that produced its type.
- Zero tests enter the suite that were never observed failing first.
- The rate of bugs re-filed at a different layer after the first fix attempt falls.

## Out of Scope

- Fixing the bug. Diagnosis ends at a change plan.
- Deciding what to build — the spec is upstream of both these disciplines.
- Reviewing craft or style. Correctness of the signal is the subject here.
