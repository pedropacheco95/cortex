# Archive — Overview

## What this is

Every document that ever authorized project work — client specifications, contracts, meeting transcripts, compliance requirements — captured once, on one pipeline, and kept verbatim forever. The outcome is that "what did we agree to, and when did it change" always has an answer held inside the project, not in someone's inbox.

## What it covers

- **Every authoritative document is captured, once, on one pipeline** — whatever the shape of the document, it enters the same way every time: classified by type, stored untouched, its structured content extracted alongside, and indexed so anyone can see what's captured and what's current versus superseded. Capturing never silently changes anything downstream — feeding a change plan is always a separate, confirmable step.

## Why it's grouped this way

This group exists because the documents that authorize rules and requirements usually live outside the project — an email, a chat thread, a shared drive — and the moment a dispute or renegotiation asks "what did the previous version actually say," the answer depends on someone's memory. Systematic capture with preserved supersession turns that from an archaeology exercise into a lookup. Keeping capture separate from change-making is deliberate: a document is evidence the moment it arrives, but it only changes the project's rules when a person reviews a plan and says yes.

What deliberately does not belong here: judging whether a captured requirement is correct, or the mechanics of the review gate itself — those belong to the review outcomes.
