# Generated Index Blocks — the atlas `_index.md` files list what is recorded

## Intent

`.cortex/atlas/decisions/_index.md` and `.cortex/atlas/evidence/_index.md` are active prompts
(schema §7.1) that say *when* to read into the directory but not *what is in it*: a session that
opens one still has to `ls` and open files to learn that the pull-only stance was reversed on
2026-08-05 or that usage was measured on 2026-09-15 — and `pulse.usage` Rule 10 found it never
did (0 reads of `atlas/decisions/` in 41 sessions). This spec makes `cortex scan` and `cortex init`
write a **generated block** into each of the two files, delimited by the schema §8 marker idiom:
one line per decision or evidence entry — date, id, title, and the subjects it bears on — newest
first, collapsing to a count line once the file would exceed §7.1's 300-token budget. Hand-written
text outside the markers is preserved byte-for-byte, `cortex sync`'s template refresh treats the
block as opaque, and a rerun that changes nothing writes nothing. It is the fourth consumer of the
recall index (schema §4.11): rendered from the compiled index, never from frontmatter, so the
block and the hooks can never disagree about what is current.

## Entities

- **READS:** the compiled `RecallIndex` (in-process, from `recall.recall-index`'s
  `compileRecallIndex` — the same object `writeRecallIndex` just serialised; the file is not
  re-read); `.cortex/atlas/decisions/_index.md` and `.cortex/atlas/evidence/_index.md`
  (current bytes).
- **WRITES:** those two files — only the region between the markers, and only when the bytes
  would change.
- **CREATES:** nothing. A missing `_index.md` is not created here (`cortex init` and
  `atlas.evidence`'s `ensureEvidenceDir` own creation); a missing directory is skipped.

## Rules

1. **Markers.** The block is `<!-- cortex:recall:start v{{SCHEMA_VERSION}} -->` … `<!--
   cortex:recall:end -->`, each marker on its own line — the §8 marker idiom with a `recall`
   discriminator so the CLAUDE.md block's tooling (`check.claude-md`, `cortex sync`) never
   confuses the two. Content outside the markers is never modified; a file without markers gets
   the block appended after its final newline, preceded by one blank line.

2. **Content, rendered from the index.** A heading line `**Recorded (generated by \`cortex
   scan\`; newest first):**`, then one line per `entries[*]` of kind `decision` (in the
   decisions index) or `evidence` (in the evidence index), sorted by `date` descending then id
   ascending:
   `- <YYYY-MM-DD> <id> — <title> · bears on: <refs>` — `<refs>` is the entry's subject
   membership, obtained by inverting `subjects` (every key whose `decided` or `evidence` list
   holds the id), sorted, at most **four**, with ` (+N)` when more; an entry present in no
   subject list renders `· bears on: —`. Ids and titles are never cut. **No body text** (the
   index carries none).

3. **Budget collapse — `check.index-shape` stays clean.** The whole file's estimate must stay
   ≤300 tokens by the validator's own estimator (`words × 1.3`, `src/schema/checks/layout.ts`),
   so the two agree. Keep the longest newest-first prefix of entry lines for which the complete
   file — hand-written text, heading line, kept lines, and the collapse line — fits; the
   remainder collapses to `- … and N more (\`cortex recall --kind <kind>\`)`. If no entry line
   fits, the block is the heading and the collapse line. If the hand-written text alone is over
   budget, the block is still written and the pre-existing overage is `check.index-shape`'s to
   report, as before.

4. **Empty means absent.** When the index has no entry of the block's kind, no block is
   written, and an existing block (markers included, plus the single blank line Rule 1 added)
   is removed. A missing `_index.md` or a missing directory → nothing is written and nothing is
   reported as an error.

5. **Idempotent and byte-stable.** The new file content is computed in full and compared to the
   current bytes; equal → no write (the mtime does not move). Two runs over identical input
   produce identical bytes. The version in the start marker is the package's `SCHEMA_VERSION`
   and is rewritten on a version change like the CLAUDE.md block's.

6. **Callers — and only these.** `writeRecallIndexBlocks(root, index)` in
   `src/recall/index-blocks.ts`, called by `cortex scan` and `cortex init` immediately after
   `writeRecallIndex` (`recall.recall-index` Rule 11; `core-cli.init` Rule 2). **Not** by the
   post-commit fast tier — the block is committed content (atlas is committed, RULES.md rule 15)
   and a git hook must not touch the working tree it just committed from. Nothing else writes
   the block. `cortex validate` never writes it.

7. **`cortex sync` treats the block as opaque.** `core-cli.sync` Rule 4's byte comparison
   against the shipped template is made on the file with the block (and its preceding blank
   line) removed; when the template text is refreshed the existing block is re-appended
   unchanged. A file whose only difference from its template is the block is `current`, not
   `localised`.

8. **Deterministic Core** (R-001): sorting, string assembly, one read and at most one write per
   file. No LLM, no network, no subprocess.

## Acceptance Criteria

### The block lists entries newest first with their subjects

- **Given** an index with decisions `decision.2026-07-07-a` (bearing on `R-001`, `schema:§5`)
  and `decision.2026-08-05-b` (bearing on `schema:§5`, `R-003`, `pulse.usage`, `src/x.ts`,
  `src/y.ts`) and the shipped `atlas/decisions/_index.md`
- **When** `writeRecallIndexBlocks(root, index)` runs
- **Then** the file ends with a block whose first entry line is `- 2026-08-05
  decision.2026-08-05-b — <title> · bears on: R-003, pulse.usage, schema:§5, src/x.ts (+1)` and
  whose second is the `2026-07-07` line, and the text above the start marker is byte-identical
  to the template

### Hand-written text outside the markers survives

- **Given** a `decisions/_index.md` whose `Read this when:` paragraph was hand-edited and which
  already carries a block
- **When** the writer runs with a changed index
- **Then** every byte outside the markers is unchanged and the block is replaced in place

### Over budget collapses to a count line and validates clean

- **Given** forty decisions with 15-word titles
- **When** the writer runs, then `cortex validate`
- **Then** the block ends with `- … and N more (\`cortex recall --kind decision\`)` with N > 0,
  the kept lines are the newest, and the report carries no `check.index-shape` warning for the
  file

### No entries, no block

- **Given** an evidence index with an existing block and a compiled index with no evidence
  entries
- **When** the writer runs
- **Then** the markers and the block are gone and the file equals the template byte-for-byte

### A rerun writes nothing

- **Given** a project whose blocks are current
- **When** the writer runs again with the same index
- **Then** both files' mtimes are unchanged

### scan and init write the blocks; the post-commit tier does not

- **Given** an initialised project with two decisions and one evidence file
- **When** `cortex scan` runs, then `cortex insight-refresh-fast` after a decision file is
  added
- **Then** after `scan` both `_index.md` files carry a block naming every entry; after the fast
  tier the blocks are unchanged while `recall-index.json` names the new decision

### sync sees a blocked index as current

- **Given** a project whose `decisions/_index.md` is the shipped template plus a block
- **When** `cortex sync` runs
- **Then** the summary counts `atlas/decisions` as current, the block is intact, and the
  template text above it is refreshed when the template changed

## Notes

- **Why a third leaf spec and not a rule on `recall.recall-index` or `core-cli.init`.** The
  index spec's contract is "writes `recall-index.json` — nothing else, ever", and init's rules are
  bootstrap; a writer of committed atlas content is one behaviour (RULES.md rule 13) with its own
  callers, budget and idempotency, and it is a *consumer* of the index, which is where the recall
  domain's overview said the consumers would live.
- **Why subjects are inverted rather than `bears_on` copied.** The index's subjects hold only
  refs that resolved and only current decisions, so the block shows what the hooks would answer.
  A superseded decision therefore renders `· bears on: —`; its own file says why. Reading
  frontmatter here would reintroduce the second source of truth the index exists to remove.
- **Why `cortex recall --kind` in the collapse line.** The overflow has to point somewhere
  that lists the rest without opening files; that verb (`recall.why` Rule 6) is it.
- **Sync's version-keyed template gap** (`src/cli/sync.ts` judgment-call note) is untouched:
  Rule 7 only strips the block before the existing comparison.
- Journey-layer tests deferred to v1.1 pending the test-runner loop (project-wide convention).
