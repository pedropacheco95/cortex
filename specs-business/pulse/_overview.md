# Pulse — Overview

## What this is

A system that keeps itself honest. The outcome is that the knowledge layer stays current on its own — surfacing unfinished work, drift, and patterns worth capturing — and proposes changes for the user to approve rather than changing anything silently.

## What it covers

_No business specs written yet — this tree is scaffolded structure only. Planned outcomes:_

- **Knowledge that stays current** — the picture keeps pace with reality without constant manual upkeep.
- **Drift surfaced early** — where understanding and code have parted ways, it gets flagged.
- **Unfinished work made visible** — loose ends are noticed instead of forgotten.
- **Patterns worth keeping** — recurring things worth capturing are proposed for inclusion.
- **Changes proposed, not imposed** — the user approves updates; nothing happens silently.

## Why it's grouped this way

This group exists because any knowledge layer rots the moment it stops being maintained, and manual upkeep never keeps pace. A system that watches for drift, unfinished work, and emerging patterns — and proposes its own corrections — stays trustworthy over time. That self-maintaining, approval-gated honesty is the outcome that belongs here.

What deliberately does not belong here is the unattended, multi-run automation that builds on prior learning — that's a related but distinct outcome. This group is about keeping the existing knowledge honest and current, with the user always in the approval seat.
